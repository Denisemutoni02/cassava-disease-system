# CassavaGuard PWA (React + Vite)

Mobile-first progressive web app for cassava leaf disease detection (CMD /
CBSD) and outbreak hotspot mapping. Online-only: diagnosis and the map need an
internet connection.

## Screens

| Screen | Route | What it does |
|--------|-------|--------------|
| Login | `/login` | Phone/email + password; uses the backend login when available, otherwise a local demo session (role aware: farmer / officer) |
| Home / Upload | `/` → `/diagnose` | Take or pick a leaf photo, optional GPS, submits to `POST /diagnose` |
| Result | `/result` | Label, confidence, risk advice, per-class model scores, buttons for map / new diagnosis |
| Hotspot map | `/map` | Leaflet + OpenStreetMap, GeoJSON clusters from the backend, High/Emerging/Low legend, your location marker |
| History | `/history` | Past diagnoses for the logged-in user (date, label, confidence) stored on the device |
| No-internet state | every screen | Red banner with a Retry button; submit stays disabled while offline |

## Requirements

- Node.js 18+ (20 LTS recommended)
- The CassavaGuard FastAPI backend running somewhere reachable
  (see `../backend/README.md`)

## Install & run

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173
```

Production build / preview:

```bash
npm run build      # outputs dist/ with service worker + manifest
npm run preview
```

On Windows you can use `..\start_frontend.bat` from the project root.

## Point the app at the FastAPI backend

Copy the example env file and change the URL:

```bash
cp .env.example .env
```

```dotenv
VITE_API_URL=http://localhost:8000
```

- `POST {VITE_API_URL}/diagnose` — the core diagnosis endpoint (no auth)
- `POST {VITE_API_URL}/api/v1/auth/login` — optional login (falls back to demo mode)
- `GET {VITE_API_URL}/api/v1/clusters/geojson` — hotspot clusters for the map
- `GET {VITE_API_URL}/health` — reachability probe used by Retry

Restart `npm run dev` after changing the env file (Vite only reads env vars at
startup). CORS must allow the frontend origin — the backend ships with
`CORS_ORIGINS=http://localhost:5173,...` in `backend/.env`.

**Mock login:** if the backend auth service is unreachable (or you continue in
demo mode) the app creates a local session and the role is picked on the login
screen. Diagnosis itself never requires a login.

## Test on a phone

1. Backend and frontend must be on the same network as the phone.
2. Start Vite with a host binding (already set in `vite.config.js`):

   ```bash
   npm run dev        # listens on 0.0.0.0:5173
   ```

3. Find your computer's LAN IP (e.g. `192.168.1.20`) and open
   `http://192.168.1.20:5173` in Chrome/Android or Safari/iOS.
   Keep `VITE_API_URL=http://<your-lan-ip>:8000` in `frontend/.env` so the
   phone can reach the API.
4. **Camera:** the upload button opens the camera on phones
   (`<input capture>`); you can always pick from the gallery instead.
5. **GPS/geolocation requires a secure context** — browsers allow it on
   `localhost` and `https://` only. Over plain HTTP on a LAN IP, GPS will be
   denied; either test GPS on `localhost`, serve the app behind HTTPS, or use
   Chrome's `chrome://flags/#unsafely-treat-insecure-origin-as-secure` and add
   `http://<lan-ip>:5173`.
6. **Add to Home Screen:** browser menu → *Add to Home screen*. The PWA
   manifest and service worker (app shell only) are generated by
   `vite-plugin-pwa` — diagnosis and map data are never cached.

## Project structure

```
src/
├── api/client.js          # fetch wrapper, VITE_API_URL, NetworkError/ApiError
├── components/            # Layout, OfflineBanner, LeafletMap, ProtectedRoute
├── context/               # AuthContext (backend + demo login), NetworkContext
├── lib/history.js         # local diagnosis history + last-result hand-off
├── pages/                 # Login, Upload, Result, MapPage, History
├── styles.css             # mobile-first CSS (~360 px baseline)
├── App.jsx                # routes
└── main.jsx               # entry
public/icons/              # PWA icons
```

## Notes

- The service worker caches **only the app shell**; API responses are never
  cached (online-only system).
- History is stored per user in `localStorage` (max 50 entries) because
  `POST /diagnose` is stateless — this is an activity list, not offline
  caching.
